# Pump.fun Dev Scanner

Telegram-бот ранних алертов по девам и трейдерам Pump.fun (реализация ТЗ от 1 ноября 2026).
Бот только находит монеты и присылает сигналы: точка входа, цель выхода, экстренный сигнал на выход.
Покупка и продажа — вручную в Axiom или приложении Pump.fun. Приватные ключи бот не хранит и не принимает.

## Режимы

| Режим | Что делает |
|---|---|
| **Девы** | Новый запуск кластера дева, который раньше повторял «запуск → рост → дамп», если до типичной зоны дампа остаётся запас под чистый профит. Сопровождение 60 минут: цель, 70% зоны дампа, продажа кластера (экстренно, со звуком, красная кнопка), нетипичное поведение, итог. |
| **Смарт-мани** | Покупки трейдеров с положительной копируемостью при задержке 5 с. Фильтрованный режим (фильтры безопасности, диапазон MC, рост за минуту, мин. сумма) и полный (лента всех сделок в отдельном топике). Консенсус, совпадение с девом, сигнал на выход при продаже трейдера. |
| **Разбор дня** | Итог серии по алертам, упущенные возможности с причиной, лучшие окна входа, новые кандидаты с кнопкой «Отслеживать», сравнение с вашими сделками. Короткая сводка + CSV. `/backtest` — прогон любых порогов с подбором на одном периоде и проверкой на следующем. |

## Архитектура

```
PumpPortal WS ─┐                     ┌─ tokens / trades / sol_transfers ─┐
Helius WS ─────┼─► ingest (приёмник) ┤   NOTIFY events                   ├─► analytics ─► outbox ─► bot ─► Telegram
Solana RPC ────┘   дедуп, досбор,    └───────────── PostgreSQL ──────────┘   кластеры,     NOTIFY    лимиты,
                   слоты, метаданные                                         профили,                топики,
                                                                             скоринг                 пауза
web: https://<домен>/p/<mint> → pump://coin/<mint> (или pump.fun на компьютере)
```

| Сервис | Модуль | Роль |
|---|---|---|
| `ingest` | `scanner/ingest` | Два независимых потока, дедуп по сигнатуре, досбор после разрывов через RPC, слоты для бандлов/снайперов (`getSignatureStatuses`), метаданные токена, переключение при тишине 30 с, сверка покрытия раз в час |
| `analytics` | `scanner/analytics` | Кластеры девов и связи кошельков, профили (медианы, повторяемость), скоринг потенциала и чистого профита, фильтры, смарт-мани, сопровождение, итоги, обратная связь, слежение за выводом SOL, ночной пересчёт трейдеров, разбор дня по расписанию |
| `bot` | `scanner/bot` | Команды и кнопки, белый список user_id, доставка очереди с приоритетами и лимитами Telegram, редактирование MC в том же сообщении |
| `web` | `scanner/web` | Страница перехода в приложение Pump.fun (только валидный адрес, только pump:// и pump.fun) |
| `db` | `scanner/db/schema.sql` | PostgreSQL 16: tokens, trades, wallets, clusters, cluster_links, launches, traders, alerts, alert_outcomes, user_marks, settings и служебные таблицы |
| `backup` | `scripts/backup_loop.sh` | Ежедневный `pg_dump`, 14 копий |

## Источники данных

Основа — собственные ончейн-данные; внешние сервисы только дополняют их (подробно — `docs/TZ.md`, раздел 16).

| Источник | Роль | Ключ | Где получить |
|---|---|---|---|
| PumpPortal | **Основной поток**: создания и сделки всех новых монет (30 минут, дольше — для растущих и отслеживаемых) | `PUMPPORTAL_API_KEY` — **обязателен для сделок** (кошелёк ключа ≥0,02 SOL; данные кривой бесплатно) | pumpportal.fun |
| Helius RPC | Слоты, переводы SOL (кластеры), холдеры, досбор после разрыва | `RPC_URL` или `HELIUS_API_KEY` | dashboard.helius.dev (бесплатный тариф подходит) |
| Helius `transactionSubscribe` | Резервный поток при обрыве PumpPortal (`HELIUS_STREAM=backup`) | тот же ключ, тариф Developer | трафик 20 кредитов/МБ — постоянно включать дорого |
| Dune | Разовая загрузка истории запусков за 30 дней | `DUNE_API_KEY` (необязателен) | dune.com → Settings → API |
| DexScreener | Цена, ликвидность, объём, бусты; режим «Тренды»; сопровождение после миграции | не нужен | — |
| GeckoTerminal | Новые и трендовые пулы (режим «Тренды») | не нужен | — |
| RugCheck | Mint/freeze authority, риски, топ-холдеры | не нужен | — |
| GMGN OpenAPI | Метки smart_degen и KOL, безопасность токена, метки и PnL кошелька | `GMGN_API_KEY` | gmgn.ai/ai |
| Jupiter Price v3 | Резервный курс SOL, цены токенов | `JUPITER_API_KEY` (необязателен) | portal.jup.ag |
| Birdeye | Цена; PnL кошелька (с платного тарифа Starter) | `BIRDEYE_API_KEY` | bds.birdeye.so |
| Solscan Pro | Метки бирж (тариф Level 2) | `SOLSCAN_API_KEY` | pro-api.solscan.io |

Нет ключа — источник выключен, бот работает дальше. Включение, лимиты и фильтры — `config/external.yaml`.
Внешние запросы идут только для кандидатов на алерт и по командам `/token`, `/dev`, `/trader`, с тайм-аутом 1 с.
Состояние каждого источника видно в `/health`.

**Добавить ключ на сервере:** `cd /opt/tg-bot && nano .env` → вписать, например, `GMGN_API_KEY=...` →
сохранить → `docker compose up -d --force-recreate analytics bot`.

Ключевые формулы (`scanner/analytics/curve.py`, `scoring.py`):

```
Потенциал     = k × MC дампа / (MC алерта + ΔMC за время реакции)      k = 0.8
Чистый профит = Потенциал × (1 − f вход) × (1 − f выход) − 1
Итог серии    = доля удачных × средний плюс − доля неудачных × средний минус
```

`f` — комиссия кривой (замеряется по реальным сделкам из `TradeEvent`, пока замеров нет — значение из конфига),
приоритетная комиссия и проскальзывание по состоянию bonding curve при заданном размере позиции.

## Развёртывание

Требования: сервер 4 vCPU, 8–16 ГБ RAM, SSD, Docker с Compose, домен с HTTPS для страницы перехода.

1. **Бот.** Создайте бота у @BotFather, получите `BOT_TOKEN`. Узнайте свой user_id (например, у @userinfobot).
2. **Супергруппа.** Создайте группу, включите «Темы», добавьте бота администратором с правом «Управление темами».
   Id группы (вида `-100…`) — в `ALERT_CHAT_ID`. Топики («Сильные алерты», «Девы», «Смарт-мани», «Полный режим»,
   «Сопровождение монет», «Разбор дня», «Система») бот создаст сам при первом `/start` в группе.
   Уведомления настраиваются отдельно для каждого топика.
3. **Ключи.** `cp .env.example .env` и заполните. Для продакшена нужен платный RPC (публичный сильно ограничен
   по частоте) и, по желанию, Helius Developer-план для второго потока.
4. **Запуск:**
   ```bash
   docker compose up -d --build
   docker compose logs -f ingest analytics bot
   ```
5. **Страница перехода в приложение Pump.fun бесплатно (GitHub Pages).** GitHub → репозиторий → Settings →
   Pages → Source: «Deploy from a branch», ветка `claude/telegram-bot-spec-fbcq7j`, папка `/docs` → Save.
   Через минуту в `.env`: `REDIRECT_BASE=https://<ваш-логин>.github.io/Tg-bot` и перезапуск
   `docker compose up -d --force-recreate analytics bot`. Либо свой домен:
6. **HTTPS для страницы перехода (свой домен).** Сервис `web` слушает `127.0.0.1:8080`. Пример Caddy:
   ```
   scanner.example.com {
       reverse_proxy 127.0.0.1:8080
   }
   ```
   `REDIRECT_BASE=https://scanner.example.com`. Если на вашем телефоне ссылка `https://pump.fun/coin/<адрес>`
   сама открывает приложение — поставьте `links.use_direct_pump_link: true`, страница не нужна.
6. **Telegram:** в настройках Telegram выключите встроенный браузер для ссылок, иначе переход может застрять внутри.
7. **История.** Профилю дева нужно минимум 3 запуска: первые дни бот копит историю (сырые сделки хранятся 30 дней,
   профили — постоянно). До этого работают смарт-мани по добавленным вручную кошелькам (`/addwallet`).

Обслуживание кластеров и истории (на сервере, в папке бота):
```bash
docker compose run --rm analytics recluster --report   # через какие адреса склеились кластеры
docker compose run --rm analytics recluster            # пересборка кластеров и профилей
docker compose run --rm -e DUNE_API_KEY=... analytics history --days 30   # история за 30 дней (Dune)
docker compose run --rm analytics verify --day 2026-11-03 --days 7       # проверка на истории → «Разбор дня»
```

Бэкап и проверка восстановления (раз в месяц):
```bash
docker compose run --rm --entrypoint /bin/sh backup /scripts/restore_check.sh
```

## Настройка

* `config/config.yaml` — все пороги, пресеты фильтров («Осторожный», «Обычный», «Агрессивный»), издержки,
  шаблоны ссылок (Axiom, GMGN, DexScreener, Solscan), адреса бирж, параметры надёжности.
  Файл перечитывается на лету — пересборка не нужна.
* `/settings` в боте — порог чистого профита, повторяемость, макс. MC входа, пресет фильтров, время реакции,
  размер позиции. Хранятся в БД и перекрывают `defaults` из YAML.

### Бумажная торговля

Семь виртуальных портфелей по $30 торгуют по одним и тем же алертам, отличаются только схемой выхода:

| | Схема |
|---|---|
| A | стоп −6%, тейк 50% на +30%, трейлинг 15% |
| B | базовая: стоп −15%, тейк 50% на +30%, трейлинг 15% |
| C | только цель алерта и экстренный выход |
| D | стоп −10%, тейк 50% на +20%, трейлинг 10% |
| E | стоп −15%, тейк 50% на +50%, трейлинг 20%, 15 мин на рост |
| F | без тейка: трейлинг 15% включается после +15%, стоп −10% |
| G | скальп: всё на +25%, стоп −8%, 5 мин на рост |

Цены открытых позиций проверяются раз в 2 с (DexScreener — одним запросом до 30 монет), тренд-монеты
сопровождаются раз в 5 с. Размер позиции зависит от силы сигнала: «Сильный» ×1.5, «Обычный» ×0.75 от
базовой доли (`/settings`, переключатель «Размер по силе сигнала»; потолок — 50% баланса).

### Фильтры «Трендов» против ботов и рагов

После базового импульса (рост, объём, ликвидность, топ-10) монета проходит ещё четыре проверки:

1. **Боты в сделках** (GeckoTerminal, до 30 пулов одним запросом): разных покупателей за 5 мин ≥ 12,
   не больше 2.5 покупки на кошелёк, покупателей хотя бы в 1.2 раза больше, чем продавцов.
2. **Лесенка и ровный объём** по минутным свечам: рост без откатов и красных свечей или одинаковый объём
   каждую минуту — работа бота. Если GeckoTerminal упёрся в лимит дважды подряд, проверка пропускается.
3. **Вход на откате**: после сигнала бот ждёт до 5 минут отката 5–20% от пика и отскока +2% от дна.
   Нет отката или обвал глубже 20% — пропуск. Выключается в `/mode`.
4. **Холдеры** (прямо перед алертом, ~22 запроса RPC, не больше 30 проверок в час): доля свежих кошельков
   в топ-10, общий источник денег (биржи и сервисы не считаются), пополнение в одно окно 10 минут.

Бусты DexScreener больше не делают сигнал «Сильным». «Сильный» — от 30 разных покупателей, вдвое больше
продавцов и чистые холдеры. Все отсеянные монеты час сопровождаются в тени: разбор дня и `/health`
показывают, что с ними стало («через час в среднем −20%, выросли бы на +30%: 2 из 140»).

### Автоподбор фильтров «Трендов»

Каждую ночь (03:00 UTC) и по `/tune`: закрытые тренд-алерты делятся по времени на обучение (2/3) и проверку (1/3).
На обучении подбираются до трёх ужесточений порогов (рост за 5 мин, давление покупок, объём, ликвидность, MC,
рост за час) и «плохие часы». Новые пороги применяются, только если на проверке средний результат на сделку
вырос и осталось ≥ 10 сделок. Ручные настройки всегда главнее; выключается в `/mode`.

## Разработка и тесты

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
# интеграционный тест использует реальный PostgreSQL
export TEST_DATABASE_URL=postgresql://scanner:scanner@localhost:5432/scanner_test
pytest
python -m scanner all      # все сервисы в одном процессе (для отладки)
```

Тесты: формулы и кривая, парсер событий Pump.fun (логи и self-CPI, новые поля в конце, ошибки), детектор крупной
продажи (1 tx и окно 60 с), кластер из слота создания, бандлы/снайперы, профиль и повторяемость, скоринг и все
условия «бот молчит», фильтры, копируемость, формат алерта (первые три строки), кнопки, сквозной сценарий
«история → профиль → алерт → экстренный выход → итог → отметка → разбор дня → бэктест → доставка в Telegram».

## Что проверить на этапе исследования (разд. 13 ТЗ)

Код написан так, чтобы эти вещи правились конфигом, но проверить их можно только на реальной инфраструктуре:

* открывает ли `pump://coin/<адрес>` приложение на вашем телефоне и формат ссылки Axiom (`links` в конфиге);
* задержки PumpPortal и Helius на вашем сервере, цена Helius-плана; LaserStream gRPC не реализован — подключать,
  только если замеры покажут, что задержка мешает зарабатывать;
* раскладка событий Pump.fun после очередного обновления программы: парсер читает известный префикс полей
  и терпит новые поля в конце; при всплеске ошибок пишет в «Система»;
* стиль кнопок (`style: danger`) зависит от версии Bot API у клиента; если сервер его отклонит, бот сам перейдёт
  на обычные кнопки.

Ограничения MVP (по ТЗ — этапы 2–3): метки KOL и «смарт-мани в монете» по внешним данным, слежение за 1000+
кошельками без роста задержки, мини-график с отметками продаж, мониторинг X. Связи кошельков вероятностные:
переводы через биржи обрывают цепочку, клиенты биржи в один кластер не склеиваются. Доля свежих кошельков
считается по топ-15 холдеров через RPC (оценка возраста по первой подписи).
