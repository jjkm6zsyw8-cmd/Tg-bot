## 0. Владелец и правила работы (обязательно прочитать)

- Владелец — русскоязычный, не разработчик; работает с iPhone через Termius. Отвечать **по-русски, коротко,
  таблицами с цифрами «по факту»**; без прогнозов «лучший/худший случай»; без непрошеных советов.
- Команды для сервера — **одной строкой** в блоке кода. Сервер: `/opt/tg-bot`, Docker Compose.
- Обновление сервера (владелец им пользуется):
  `cd /opt/tg-bot && git stash && git pull && git stash pop && docker compose up -d --build`
  (если локальных изменений нет, `git stash pop` выдаст ошибку и цепочка остановится — тогда без stash:
  `cd /opt/tg-bot && git pull && docker compose up -d --build`).
- **Ограничения владельца (действуют):**
  1. Ключи: никогда не просить и не показывать в чате. С 17.11 по просьбе владельца кошельки можно создавать
     кнопкой в Telegram — их ключи хранятся в базе ТОЛЬКО зашифрованными (AES-256-GCM), ключ шифра REAL_MASTER_KEY —
     в .env, виден только сервису analytics. Вывод денег — только на адреса из REAL_WITHDRAW_TO (.env).
  2. Реальная торговля — **только** после положительного итога бумажной торговли за **2+ недели** и
     **отдельного решения владельца**. Честный учёт бумаги идёт с 13.11.2026 → не раньше ≈27–28.11.2026.
  3. «Не ломай то, что уже работает». Тесты на парсер, расчёт MC и симуляцию сделок обязательны.
  4. Ставки не выше ~$20–30; не советовать крупные депозиты.
- Цифры — только проверенные. Владелец жёстко реагирует на завышенные/неверные цифры и метания.
- Коммиты: в конце сообщения — строки атрибуции из системных инструкций сессии; PR не создавать без просьбы.

## 1. Цель проекта

Telegram-бот для pump.fun (Solana): следит за потоком запусков и сделок, находит прибыльные паттерны
(девы-«конвейеры», smart-money кошельки, свои кошельки владельца), шлёт сигналы, **ведёт бумажную торговлю 24/7**
как реальный бот и (новое) **реальный бот** с режимами выкл/тень/бой. Цель владельца — автоматическая
прибыльная стратегия ($50–100/день), бот сам учится, какие кошельки копировать.

## 2. Архитектура

```
PumpPortal WS ─┐                      ┌─ tokens / trades / ... ─┐
Helius WS ─────┼─► ingest (приёмник) ─┤      PostgreSQL 16      ├─► analytics ─► outbox ─► bot ─► Telegram
Solana RPC ────┘   дедуп, досбор       └──── NOTIFY events ──────┘   сигналы,     (очередь)  команды,
                                                                     бумага,                кнопки, темы
                                                                     РЕАЛЬНЫЙ БОТ ──► Helius RPC / Sender ─► Solana
web: страница перехода в приложение Pump.fun          backup: pg_dump раз в сутки
```

Сервисы (`docker-compose.yml`, общий образ `Dockerfile`, все читают `.env`):

| Сервис | Команда | Роль |
|---|---|---|
| db | postgres:16 | база |
| ingest | `python -m scanner ingest` | потоки PumpPortal/Helius, разбор событий pump.fun и PumpSwap, запись в БД |
| analytics | `python -m scanner analytics` | движок: кластеры девов, smart-money, сигналы, бумага, **реальный бот** (единственный сервис, которому виден `REAL_PRIVATE_KEY`) |
| bot | `python -m scanner bot` | Telegram: команды, кнопки, доставка outbox по темам |
| web | `python -m scanner web` | редирект в приложение Pump.fun |
| backup | sh-скрипт | ежедневный дамп, 14 копий |

Связь сервисов только через БД: таблица `outbox` (сообщения в Telegram), `jobs` (команды из бота в
аналитику, NOTIFY `jobs`), `settings` (настройки владельца, NOTIFY `settings` → аналитика перечитывает),
`kv` (состояния для отчётов, например `real:status`, `paper:entry_stats`).

## 4. Модули по смыслу

### 4.1 Сбор данных
- **ingest/receiver.py, sources.py** — PumpPortal Data API (основной поток), Helius WebSocket (резерв и
  подписки на нужные адреса), досбор пропусков через RPC, дедуп по подписи.
- **ingest/pump_parser.py** — события pump.fun (Create/Trade) и PumpSwap (Buy/Sell). Важно: у создания читается
  `quote_mint` (пара не к SOL → None/адрес), у PumpSwap MC считается по **эффективным резервам**
  (`pool_quote + virtual_quote_reserves`, ~17.5 SOL виртуальных у текущих пулов).

### 4.2 Мониторинг кошельков и паттерны
- **Кластеры девов** (`clusters.py`, `profiles.py`, `scoring.py`): склейка кошельков дева, профиль «запуск → рост →
  дамп», сигнал «Девы».
- **Smart-money** (`copytrade.py`): копируемость трейдера при задержке входа; фильтры; сигнал smart.
- **Свои кошельки** (`/addwallet`, `/import` с пометкой источника pump.fun/axiom/gmgn и отбора
  реализованный/нереализованный PnL, `origin.py`, `wizard.py`): копии и «мой дев» (запуски девов из списка).
- **Разведка** (`scout.py`): сама ищет кандидатов среди лучших трейдеров монет, испытывает в портфеле H,
  прошедших переводит в smart (pinned), скальперов в минусе удаляет.
- **Соседи лучшего кошелька по блокчейну** (`cobuy.py`, CLI `cobuyers [кошелёк] [--coins 60] [--queue]`, с 18.11):
  по последним покупкам кошелька (из своей базы — время и слот) берёт из блокчейна сделки монеты в окне −90…+40 с и
  считает, кто покупал раньше него / в том же блоке / после (копировщики). Ручная проверка 18.11 по 2 монетам 7BNax:
  в том же блоке оба раза — `nnnBBf…znUj` (торгует, ~41 SOL) и `8vLYny…Etp5` (остановился 17.11 11:13, как 7BNax,
  перевёл 36.8 SOL на `ssssssA47…5thY` — торгует на PumpSwap); раньше него — `2tgUbS…JUvY`, `sssssv2i…T2NT`.
- **Весь PumpSwap через Dune** (`dunescout.py`, с 18.11): ключ `DUNE_API_KEY` (бесплатный). Раз в сутки, в фоне,
  запрос к `dex_solana.trades` (площадка `pumpswap`; можно задать `DUNE_SCOUT_TABLE` / `DUNE_SCOUT_PROJECT`):
  копия по правилу A за сутки для каждого кошелька с 10–300 покупками по 0.3–5 SOL; тейк 60%+, в среднем +10%+,
  быстрых сбросов ≤30% → в разведку (score 5000+), испытание в S. Первый запуск проверяет таблицу и площадку.
  Вручную: `docker compose run --rm bot dune-scout [--queue]`. GMGN не подключён: ключ требует $100 на балансе.
  ВНИМАНИЕ: запрос к Dune ещё ни разу не выполнялся на настоящих данных — первый запуск покажет ошибки схемы/кредитов.
- **Семья лучших кошельков** (`family.py`, с 18.11): по деньгам, а не по сделкам. Лучший smart молчит 2+ ч → его
  крупные переводы → копилка → её крупные переводы → обменник → другие копилки, сливающие в тот же обменник → их
  торговые кошельки (прибыль за 3 дня) → в разведку первыми (score 10000), испытание в H. Найдено вручную 18.11:
  7BNax → Ce8vr (копилка, 7376 SOL с июля) → EnvMK (обменник) ← Askojg, F6DxYF (копилки того же владельца, слив в ту же
  минуту) ← Ar2Y6o1Q…ro1x (торгует сейчас: 1000 транзакций за 10 ч, PumpSwap, ~120 SOL). Адреса-двойники (отравление
  адреса, 0 SOL) пропускаются. Раз в 15 мин, сотни запросов RPC один раз на копилку, дальше — единицы.
- **Испытание по правилу боевого бота** (с 18.11): кандидаты разведки копируются в два портфеля — H (правило G, для
  сравнения) и **S** (правило A, как торгует бот: вход через 2 блока, всё на +25% без стопа, выход за трейдером, до
  30 мин, по $10). Решение — по S (`verdict_a`): 8+ копий, в плюсе 65%+, в среднем +5%+ → в smart; 5+ копий и в плюсе
  меньше 30% или 4 в минусе подряд → отсев сразу. Чистка smart-кошельков разведки — по последним 10 копиям в A.
  Почему: у 7BNax собственный винрейт 51% (+12% на сделку, держит ~5 мин), а копия по A — 81% (+28%): цена после его
  покупки сразу растёт, бот забирает +25% за ~30 с. У Ar2Y6o1 (та же семья) — 54%, +1.4%, держит 13 с.
- **Испытание разведки** (с 18.11): до 40 кошельков одновременно (было 20 — было забито); за сутки меньше 2 копий —
  «почти не торгует», место следующему, вернуться может через 2 дня.
- **Разведка «рядом со smart»** (`scout.discover_cobuyers`, с 18.11): кандидаты — кто покупал те же монеты, что
  smart-кошельки в плюсе на бумаге A (неделя), в ±10 мин от их покупки, на 2+ монетах за 3 дня и покупал за
  последние сутки (`scout_cobuy_min_coins`, `scout_cobuy_active_h`; с 18.11 вечера — было 3 монеты и 6 ч, кандидаты
  кончились). Dune: бесплатный план аккаунта — 0 кредитов в месяц, запросы через API только платно (проверено 18.11:
  «datapoint limit»; параметр performance=medium API не принимает — убран). Владелец: пока без GMGN и платных. Нужно для PumpSwap:
  своя база сделок там неполная (18.11: у монет 7BNax PumpPortal — 0 сделок, свой разбор блоков — с пропусками;
  AKyrm7: бумага видела пик 302, в базе 218), а испытание в H идёт по цене блокчейна — оно и проверяет.
- **Поиск по образцу smart A** (`lookalike.py`, с 18.11): ищет кошельки «как 7BNax» — после их покупки цена
  сразу растёт. Раз в 3 ч по своей базе сделок для активных кошельков считает копию по правилу A на истории —
  покупки на кривой в первые 25 мин монеты и на PumpSwap, если монету записывали ещё до покупки (7BNax торгует
  только на PumpSwap: 1080 покупок за 13–17.11, медиана возраста монеты 198 мин). PumpSwap в автопоиске пока
  ВЫКЛЮЧЕН (`lk_amm`): у 7BNax расчёт дал 10% тейков, −9.7% против 81% / +28% у бумаги A — подозрение на смесь
  источников цены (PumpPortal marketCapSol без виртуальных резервов против своего разбора блоков); разбор по монетам:
  `docker compose run --rm bot lookalike --hours 96 --all --coins <кошелёк>` (вход через 2 блока, +25% чистыми за 5 мин, выход за трейдером). 10+ покупок, тейк ≥60%,
  в среднем ≥+10%, быстрых сбросов ≤30% → статус `lookalike` в `scout`; каждый час — та же проверка только на его
  покупках после находки, решение при 10 новых (не раньше 3 ч) → в smart (метка 🧬, до 5 шт.; чистка — общая `demote` по копиям в G) или отсев на 7 дней. Обычная разведка таких
  отсеивает: копия в H заходит позже («дельта входа +43%» у 7BNax). Вручную:
  `docker compose run --rm bot lookalike --hours 96 --all <кошелёк>` (`--all` — все его покупки на PumpSwap,
  `--age N` — на кривой до N мин; в конце — разбор кошелька: площадки, возраст монет, размер). Сводка — в /scout.
- **Рейтинг** (`rating.py`): уровни кошельков (top / normal / paused) по итогам копий.
- **Автофильтр** (`autofilter.py`): учится на сделках трейдеров, какие сигналы копировать.
- **Тренды** (`trends.py`): монеты, которые продвигают (DexScreener, GeckoTerminal), со своими фильтрами.

### 4.3 Бумажная торговля (`analytics/paper.py`)
Исполнение как у реального бота: вход по цене **блока +2** после покупки трейдера (худшая для покупки цена
блока, все сделки блока разбираются через RPC), без угадываний — цену не узнали, сделки нет; сверка входа через
30 с (расхождение >10% → ⚠, сделка не идёт в итог и в баланс); стоп/тейк по каждой сделке монеты, продажа по
худшей цене блока +2; монеты в паре не к SOL — не входим.

Портфели (активные):

| Портфель | Что | Правила |
|---|---|---|
| A | smart | всё на +25% чистыми, без стопа, до 30 мин |
| B | smart | 70% на +25%, остаток трейлинг 15%, без стопа, до 30 мин |
| G | smart | всё на +25%, стоп −8%, 5 мин без +10% — выход, до 30 мин |
| M | боевая smart | как A, позиция ≤30% баланса, дневной стоп −25% |
| H | наблюдение: разведка и копии своего списка | как G, по $10, старт $1000 |
| Y | мой дев: запуски девов из списка, вход через 2 блока после создания | как G, по $10, старт $1000 |
| K | крупные копии (трейдер от 5 SOL) | как G, по $10 |
| R | смарт-ракеты (держатели ≥30 мин) | трейл 35% после +30%, стоп −50%, до суток, по $10 |

C, D, E, F новых сделок не открывают. Копии своего списка с 12.11 — только наблюдение (неделя в минусе).

### 4.4 Реальный бот (`scanner/real/`) — подробно в `docs/REAL_BOT.md`
- Сигналы: те же, что у бумаги M (smart) и Y (мой дев); `paper.on_alert` вызывает `real.on_signal`.
- Режимы: off / **shadow (по умолчанию)** / live. Live — только `REAL_LIVE=1` + `REAL_PRIVATE_KEY` + кнопка.
- Сделки собираются самим ботом: pump.fun v3 (`buy_exact_quote_in_v3`, `sell_v3`, 17 счетов), PumpSwap v2
  (`buy_exact_quote_in_v2`, `sell_v2`, wSOL в той же транзакции). Проверено симуляцией в живой сети.
- Белый список инструкций перед подписью (`tx.check_instructions`).
- Отправка: Helius Sender (`swqos_only`, `mev-protect`, чаевые 0.00001 SOL) + обычный RPC (не чаще 1/1.1 с).
- Учёт по факту транзакции (`tx.fill_from_tx`): токены, SOL, залоги счетов.
- Выход — та же `decide_exit`, схемы A (smart) / G (мой дев) по умолчанию.
- Журнал `real_orders` (заявка пишется до отправки), позиции `real_positions`, восстановление после перезапуска.
- Telegram: `/real` (`report.py`), тема «Реальный бот». Проверка на сети: кнопка или `real-check`.
- **Методы торговли** (`settings.METHODS/SCHEME_KEYS`, `executor.kinds_of`, `wallets_ui.methods_view/method_view`):
  smart, мой дев, крупные копии (K), копии своего списка и разведки (H), смарт-ракеты (R). У каждого метода — вкл/выкл,
  правило выхода A/B/G/R (любое), своя ставка (`real_stake_usd_<метод>`), у smart — отбор «все» или «как M»
  (`real_smart_filter=m`: только сигналы, которые бумага пустила в M). Всё это у каждого кошелька и в общих настройках.
- **Несколько кошельков** (`desk.py`, `vault.py`, `wallets_ui.py`): `/real → 👛 Кошельки` — создать (адрес для
  пополнения сразу), пополнить, вывести (только на REAL_WITHDRAW_TO), режим/настройки/стоп/продать всё у каждого
  своё, удалить. Движок держит `RealDesk`: по полосе `RealTrader` на кошелёк (`wallet_id` в real_positions /
  real_orders); пока кошельков нет — общая полоса без кошелька (тень). Аварийный выход: `real-export` на сервере.

## 6. Важные параметры

- Настройки владельца — таблица `settings` (ключ `user`), меняются в боте (`/settings`, `/mode`, `/real`).
  Действующие = `config/config.yaml` (defaults) + переопределения.
- Бумага: `paper_*` (см. `bot/handlers.py` NEW_DEFAULTS, `paper.py` константы), часовой пояс сброса
  `paper_reset_tz` = Asia/Tbilisi (Батуми).
- Реальный бот: `real_*` — все в `scanner/real/settings.py` с границами; жёсткие пределы — `.env`:
  `REAL_LIVE`, `REAL_MAX_STAKE_USD` (30), `REAL_PRIVATE_KEY`, `REAL_WALLET`.

## 11. Как работать с кодом

- Тесты: `service postgresql start` (в песочнице), затем `.venv/bin/python -m pytest -q`.
- Проверка реального бота на сети из песочницы: публичный RPC через прокси; см. `scanner/real/selfcheck.py`.
- Миграции — `scanner/db/schema.sql` (только `CREATE … IF NOT EXISTS` / `ALTER … ADD COLUMN IF NOT EXISTS`).
- Новая настройка реального бота — строка в `scanner/real/settings.py`; кнопки появятся сами.
- Не трогать без теста: `tx.check_instructions`, `paper.decide_exit`, `pump_parser.py`.
